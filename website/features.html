Product capabilities

Designed for the whole inspection loop.

Move from a path to a preview, from a preview to an edit, and from an edit to a terminal command without scattering your attention across disconnected windows.

01 / Navigation

A compact explorer with room to think.

Keep project structure close without letting navigation consume the workspace.

Directory browsing

Navigate project trees, select files and reveal useful file information.

Dual-pane workflow

Where enabled, use a second pane for side-by-side file operations and transfers.

Safer file operations

Use the filesystem operation and trash integrations available in the current Linux environment.

02 / Preview & inspector

One selection. Multiple ways to understand it.

The preview subsystem chooses a suitable inspection path using file information and format detection. It is designed to make more than source code visible from the same workspace.

  • Source and plain-text inspection with syntax highlighting.
  • Markdown and structured data such as JSON, YAML and CSV.
  • Image, SVG and media metadata inspection.
  • Archive browsing, SQLite inspection and hexadecimal views.
  • PDF and Office document extraction where supported by the implemented parser or optional tools.
Preview coverage varies by file format. Some media and document workflows depend on optional system utilities such as FFmpeg or Poppler. See the installation guide for the current dependency notes.
03 / Editing

Move from inspection to editing.

The editor is integrated into the workstation and uses a Rope-based text buffer.

⌘

Rope-backed editing

Buffer operations, cursor movement, selections and undo/redo are implemented around the editor's text model.

Aa

Syntax and language services

Syntax highlighting, completion layers and LSP integration where a compatible server is available.

↔

Unicode-aware behavior

Text coordinates and terminal display width require different representations; the editor and rendering layers account for these distinctions.

↶

Data protection

Inspect the actual save, undo and recovery behavior in the implementation and its tests.

04 / Developer workflow

Keep your supporting tools within reach.

Integrated PTY

Open a Linux pseudo-terminal drawer for shell commands and interactive workflows. It can remain hidden until needed.

Workspace search

Search filenames and file contents, navigate matches and cancel work when the query or project changes.

Git workbench

Inspect repository status, review changes and use supported staging and commit operations.

Task execution

Run configured developer tasks through the application's task execution and workspace trust mechanisms.

System visibility

View system and process information through the integrated monitoring interface where enabled.

Keyboard-first control

Access actions, settings and navigation through the application's shortcut and command systems.

05 / Extensibility

Extend the workflow. Keep control at the host.

TermExplorer's plugin direction uses WebAssembly components and host-mediated capabilities. Plugin permissions and resource constraints should be reviewed before enabling an extension.

  • Manifest and component validation.
  • Explicit permission handling.
  • Host-controlled APIs.
  • Execution and memory constraints.
